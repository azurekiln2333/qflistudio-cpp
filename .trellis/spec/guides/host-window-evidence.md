# Serial host execution and evidence

Use one fresh named grant for each SDK, compiler, WSL, or build window. Prepare frozen inputs before requesting the window. Never replay a consumed grant. A grant binds the actual current input bytes, including dirty shared-core files when applicable; a HEAD hash alone does not describe those bytes.

Bound the complete interval from ACCEPT through the final observer publication. Runner duration alone is not end-to-end compliance. Reserve time for cancellation, exact process observation, metadata restoration, and publication. A source-only readiness withdrawal retires the pending request without implying execution.

Start Windows children suspended and assign a private kill-on-close Job before resume. Retain exact process handles and creation times until terminal observation and active-process count zero. Root exit alone does not prove descendant exit. A tool observation timeout is not process termination. On Linux, use private process groups with recorded leader identity and prove every owned group empty after reaping. Treat permission/identity errors as unknown, not empty. Signal handlers latch cancellation so cleanup can finish. These groups do not contain deliberately escaped sessions.

Publish final RELEASE only after the outer command and all exact owned jobs/groups are terminal and empty. Keep ownership with HOLD if cleanup is unknown. An in-process auto-release can precede its publisher's exit; preserve that distinction. Report actual ACCEPT/final-publication timestamps and any budget overrun even if the runner itself was fast.

For compiler baselines, preserve per-case source/input/expected-output hashes, command/exit/output bytes, exact process identities, sidecars and ledger cross-checks. Recompute case success from actual steps rather than trusting reported success flags. Keep full original ID inventories and explicitly document output normalization. Freeze and recheck tools/SDK inputs. Host compiler success does not prove packaged binary-to-source correspondence, current OHOS package success, or installed-device execution.

The October 26 experimental snapshot is under tool/host_baseline. Its scripts preserve reviewed bytes and require restoration under build before use. The task research host-controls-20261026 and host-baseline-20261026 folders preserve raw historical evidence and limits. Keep raw contradictory author boilerplate auditable; explain it in companion documentation rather than silently editing execution evidence.
