## Reading the evidence correctly

**The stale `unrun` text is preserved raw.** `linux-control-result.json` still contains
`"unrun": "Live control window not executed by this candidate author."`. That string is
leftover author boilerplate from the candidate template and was not edited. The executed
proof lives in separate fields of the same file: `complete: true`,
`stepsObserved: 5`, and five cases with observed PIDs, exit codes, and `stdoutSha256`.
The `unrun` string must not be read as a claim that the run did not happen. The proof
and the boilerplate are two separate things in one file, and the raw bytes are kept so
the boilerplate stays auditable.

## Scope

`linux-control-result.json` sets `hostOnly: true` and
`installedDeviceEvidence: false`. These eight controls establish host-side process
containment and cancellation behaviour. They do not establish:

- compiler output or WASI runtime behaviour;
- packaged HAP content or signature;
- installed-device behaviour on OHOS.

Native and WASI evidence is owned separately by root. Do not reuse this folder as
compiler or device proof.
